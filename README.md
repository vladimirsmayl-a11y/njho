# ЛВС — Лучшая Версия Себя

Сайт (Next.js) + API (FastAPI) + Telegram-бот (Aiogram 3) + PostgreSQL.

```
lvs/
├── backend/            # API и бот: общий пакет, одна база
│   ├── app/            # FastAPI: авторизация, кабинет, админка
│   └── bot/            # Aiogram: /start, события групп, сверка подписок
├── frontend/           # Next.js 14 + Tailwind + Framer Motion
└── docker-compose.yml  # локальная PostgreSQL
```

## Как это работает

**Вход через Telegram**
1. Сайт: `POST /auth/session` → токен + секрет, привязанный к браузеру (cookie). Пользователь уходит на `t.me/lvs_key_bot?start=<токен>`.
2. Бот: `/start <токен>` находит пользователя по `telegram_id` или создаёт нового (временный ник `user_123456`, случайный пароль в виде bcrypt-хэша) и подтверждает сессию. В ответ присылает кнопку «Авторизоваться на сайте» с одноразовым кодом.
3. Сайт: страница входа сама опрашивает статус и входит, либо вход происходит по кнопке из бота в любом браузере. Результат: JWT в httpOnly-cookie.

Токен из deep link сам по себе войти не позволяет (нужен секрет браузера или код из личного чата). Иначе любой мог бы прислать жертве чужую ссылку и войти под её аккаунтом.

**Подписки**
- Paywall добавляет оплатившего в закрытую группу тарифа. Бот ловит `chat_member`, определяет высший тариф по всем группам и пишет его в базу. Pro и Премиум получают приветствие в личку, Стандарт — тишина.
- Выход или удаление из группы → `inactive`. Бэкенд проверяет подписку по базе на **каждый** запрос: следующее действие пользователя на сайте получает 402, и кабинет показывает плашку «Ваша подписка истекла».
- Страховка: раз в `RECONCILE_INTERVAL_HOURS` бот сверяет активных пользователей с составом групп (на случай, если событие пропущено). При сбое Telegram тариф не понижается.
- Тариф «Стандарт» даёт только канал. В кабинет пускают Pro и Премиум (и админов).
- Админ может выставить тариф вручную. Тогда стоит флаг «Ручной тариф» и бот его не трогает.

## Запуск локально

```bash
docker compose up -d                       # PostgreSQL

cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                       # заполните BOT_TOKEN, ADMIN_TELEGRAM_IDS, JWT_SECRET
uvicorn app.main:app --reload              # API на :8000 (таблицы создаются при старте)
python -m bot.main                         # бот (в другом терминале, из папки backend)

cd ../frontend
npm install
cp .env.example .env.local
npm run dev                                # сайт на :3000
```

Кнопки Telegram принимают только публичные https-ссылки. Для проверки входа локально запустите туннель (`cloudflared tunnel --url http://localhost:3000` или ngrok) и поставьте его адрес в `SITE_URL`.

## Настройка Telegram

1. Токен бота — в `BOT_TOKEN` (BotFather → `/mybots` → API Token).
2. Добавьте бота **администратором** во все закрытые группы и каналы тарифов. Без этого Telegram не присылает события `chat_member` и не отвечает на `getChatMember`.
3. ID групп (число вида `-100…`) узнайте через @getidsbot и впишите в `STANDARD_CHAT_ID`, `PRO_CHAT_ID`, `PREMIUM_CHAT_ID`.
4. Свой Telegram ID впишите в `ADMIN_TELEGRAM_IDS`: при первом входе получите `is_admin`.
5. Приветствие в личку приходит только тем, кто хоть раз запускал бота (то есть входил на сайт). Остальным Telegram не даёт написать первыми.

## Деплой

**Railway** (корень сервисов — папка `backend`), три сервиса:
- PostgreSQL (плагин). `DATABASE_URL` подставится в формате `postgresql://`, код сам переключит драйвер.
- API: старт `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
- Бот: старт `python -m bot.main`. Публичный домен не нужен. **Запускайте ровно один экземпляр**: два бота с polling будут конфликтовать.

Переменные: `DATABASE_URL`, `JWT_SECRET` (`python -c "import secrets; print(secrets.token_urlsafe(48))"`), `COOKIE_SECURE=true`, `SITE_URL=https://ваш-сайт`, `BOT_TOKEN`, `BOT_USERNAME`, `ADMIN_TELEGRAM_IDS`, `*_CHAT_ID`. API не стартует с `JWT_SECRET=change-me` при `COOKIE_SECURE=true`.

**Vercel** (корень — папка `frontend`): `BACKEND_URL` = адрес API на Railway, `NEXT_PUBLIC_PAYWALL_STANDARD/PRO/PREMIUM` = ссылки на оплату. Запросы `/api/*` проксируются на бэкенд, поэтому cookie сессии работает без настройки CORS.

## Что заменить перед запуском

- `frontend/content/reviews.ts`: сейчас там заглушки. Нужны реальные отзывы с согласия авторов.
- `frontend/app/privacy` и `frontend/app/terms`: заготовки, тексты должен подготовить юрист.
- Ссылки на оплату в Paywall (переменные `NEXT_PUBLIC_PAYWALL_*`).

## Что стоит знать

- **Срок подписки в ТЗ не указан.** На лендинге цены показаны без «в месяц» и т. п. Срок определяется настройками Paywall, который сам удаляет из группы.
- **152-ФЗ.** Если у вас пользователи из РФ, хранение их персональных данных, скорее всего, должно быть на серверах в России. Railway и Vercel за границей: обсудите с юристом до запуска.
- **Миграции.** Таблицы создаются через `create_all`. Для изменения схемы в продакшене подключите Alembic.
- **Лимиты запросов** (вход по паролю, создание сессий) хранятся в памяти процесса. При нескольких инстансах API перенесите в Redis.
- **Аватарки** лежат в базе (до 1 МБ), чтобы не зависеть от файловой системы Railway. При росте базы вынесите в S3-хранилище.
- **Рассылка из админки** идёт фоновой задачей API со скоростью около 20 сообщений в секунду. Для тысяч получателей лучше вынести в очередь.
- Админ входит в кабинет без подписки (чтобы поддерживать пользователей).
